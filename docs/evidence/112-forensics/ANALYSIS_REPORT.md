## 可能根因（全部待验证）

1. **模型投影承担了观测筛选的硬判据，待验证。** `lib/corners/corner_edge_fit.cpp::fitObservedEdgePair` 在拟合前逐像素检查到指定有限模型边的距离，任一像素越界即可清除该边身份；`matches` 又要求方向和位置。父变换来自工作图三 L 对应，原图观测边则在另一个分辨率下提取。父变换偏差、有限端点偏差或局部边界噪声可能使真实连续支持先被删除。合并日志不能区分方向和位置，更不能证明哪类是实际主因。
2. **连续弧端点及连接弧表示可能过度耦合，待验证。** 简化顶点及其附近真实端点生成连续区间；区间以到两端的欧氏距离修剪，然后用原始轮廓绕行长度约束连接。`connection` 次数很大可能只是枚举大量不相邻弧对的必然结果，不能据此宣称连接门控造成同等比例漏检。`short_or_residual_arc` 同时包含去重点不足、跨度不足和平均残差超限，不能据此断言应使用鲁棒拟合。
3. **局部取证失败不能表达父假设已被反证，待验证。** `lib/pipeline/decode_stage.cpp::decodeStage` 对失败角设 `unresolved=true`；若另一假设成功也拒绝发布。保守行为可从源码确认，但失败竞争是否为同一父的重复表示、错误绑定或真实第二解，仍需针对帧证据判断，不能直接删除竞争候选。

## 结构性修复方向（提议，未实施）

### 方案一：分离父投影搜索提示与原图测量验证

- **改什么：** 在 `fitObservedEdgePair` 和 `matches` 中拆分搜索候选生成、观测直线量测、模型关联验证。先从已唯一绑定的真实原图组件上按拓扑形成局部外边，再对多条真实边与模型联合匹配；对父模型和原图观测做明确坐标及有限端点对账。保持真实支持、四角独立证据和发布校验，不以预测交点填角，不更改公共接口或 Detection。
- **为什么：** 当前候选在拟合前即受每像素有限模型边门控，合并原因表明该路径有大量淘汰，但尚不能证明被淘汰的包含真实边。应优先取证父投影偏差与观测偏差，再决定职责拆分。
- **预期效果：** 潜在作用范围为本轮角点失败所在的 112/112 帧；这只是进入该路径的覆盖上限，实际恢复比例未知，需进一步取证，不能承诺 100%。
- **代价/风险：** 中到大规模内部重构；候选变多可能提高耗时，并引入内侧平行边误关联。必须保留拓扑、独立支持和竞争解检查，固定阈值验证新增误检与已有成功帧回退。

### 方案二：以轮廓拓扑建立外边邻接图，分离各门控

- **改什么：** 在 `fitObservedEdgePair` 中建立按轮廓索引排序的真实支持段与凸转折邻接图，替代所有合格弧的全排列配对；端点选择、沿弧回走、有效跨度、拟合残差、连接长度及有限支持延伸分别建模和记录。任何去重/栅格回走建模须保留原始证据映射并同步检查 `validateCornerEvidence`，不能通过丢弃不利像素制造达标结果。
- **为什么：** 大量连接拒绝以及短支持/残差混合说明目前表示和诊断无法区分“枚举了非邻接组合”与“正确邻接外边不达标”；图表示可让真实邻接成为显式约束，也可定位简化/修剪产生的支持损失。
- **预期效果：** 112/112 帧出现相邻边取证失败，为待验证覆盖上限；恢复率未知。首先期望减少无意义弧对枚举及提高可解释性，性能改善和召回改善均需实测，不将拒绝次数折算为恢复帧数。
- **代价/风险：** 中规模重构，可能降低配对成本，但轮廓尖刺、圆角、分叉和重叠区间会使邻接图复杂；仅保留相邻简化段会漏掉被栅格圆角拆开的长外边，应支持多个连续段组成真实支持。

### 方案三：为竞争假设区分“证据不足”和“已反证”

- **改什么：** 在 `decodeStage` 及内部角点解析结果中引入内部失败分类和父假设来源关联；相同物理绑定的重复假设先按真实证据归并，只有存在可复核反证的竞争候选才可排除。证据不足仍保留 unresolved，不改公开 Detection，不填历史框。
- **为什么：** 本轮有成功测量却因另一取证失败候选而未发布的记录，说明局部失败状态传播到全局发布门控。需要证明该失败竞争是否真的独立，才有理由改变处理。
- **预期效果：** 直接可讨论的范围仅 1/112 帧（约 0.89%），实际可恢复为 0–1 帧，因没有证明失败竞争已被排除。这一方向与前两项覆盖重叠，不能相加为恢复率。
- **代价/风险：** 小到中规模内部改动、额外关联判断成本；错误反证可能输出不唯一方向或错误几何，需正反竞争夹具及固定阈值回归。

以上均为设计提议。纯阈值放宽、显示历史补框和已撤回的参数组合均不列入修复方案。

## 取证方法与复现

在仓库根目录执行：

```bash
cmake -S src/tushenghao -B /tmp/marker-112-build -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/marker-112-build --target marker_app -j4
/tmp/marker-112-build/marker_app --video data/raw/marker_video.avi --config src/tushenghao/config/detector_verification.yaml --mode debug --run-purpose verification --expected-frames 1676 --run-dir docs/evidence/112-forensics/run
python3 /tmp/analyze_marker112.py
```

运行目录必须是新路径；重跑使用另一目录并同步调整脚本中的输入路径。分析脚本放 `/tmp`，中文注释说明用途，不提交。为跨机器复现，脚本正文另保存为 `analysis_method.txt`（方法归档文本，不是生产代码）。构建和运行日志、全量 `run/frames.jsonl`、112 行 `selected_frames.jsonl`、原始选择输入的 SHA256 与视频 SHA256 均已存档。

选择规则：读取 `flicker_sequence.json` 的每个 run，以闭区间 `[first,last]` 展开，按 `frame_id` 精确匹配；校验唯一集合和匹配记录均为 112，全量记录为 1676。只统计 `result.diagnostics` 一次，不重复累加 `events` 和 `details` 内相同消息。候选拒绝、帧覆盖、弧拒绝和弧对拒绝分别计数。

`forensics_summary.csv` 的单位为阶段内假设/测量。geometry_validation 可直接以 generated 与 validated 作差；assignment_admission 的输入为已补全分支，使用 assignment 拒绝事件；corner_resolution 使用角点首次拒绝事件；screen_and_evidence_validation 使用筛选事件和 measurements 对账；semantic_and_publication 使用 measurements 与 detections 对账。补全可分支，不能把 validated 与 completed 的差当拒绝数。components、observations 与 generated 是不同单位，不可相减成筛选损失。capture、preprocess、visualize、wait、export 不是候选筛选阶段；其候选进入/拒绝/通过数不适用。角点 P0→P3 首次失败即短路，失败角分布不是四角全量失败分布。
