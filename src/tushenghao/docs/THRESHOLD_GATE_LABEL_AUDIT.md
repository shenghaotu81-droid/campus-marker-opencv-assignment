# 主链阈值、门控、标签审查清单（只审不改）

审查日期：2026-11-06；分支已确认`refactor/vision-lean-fixed`，HEAD=`f1ee955`。按当前工作树行号定位。开始时已有用户未提交修改：detector.yaml、cli_options.hpp、config/detector/config.cpp、marker/main.cpp；本次不覆盖、不格式化、不提交这些文件。只新增本文，不更新flow-guide，不改已验证行为。

读法：**门**会拒绝候选、整帧、更新或输出；**标签**只附带信息；**计算/选择**产生测量或选择一个候选，不应把所有数值参数都误叫门控。建议仅用“保留／删除／门控改标签”；“删除”包括删掉只为该检查服务的配置、传递、验证和测试，而非仅把if藏进另一个模块。

证据标记：**R**=既有实拍录像可直接复算；**C**=真实录像＋原合成profile的条件G4诊断；**F**=冻结旧实拍输入反例；**T**=只有合成/坏输入测试；**U**=未找到真实触发证据。正常运行用到了一个参数，不等于证明它拒掉过坏结果；检测588帧未检出没有逐门归因，不能替每个检测门背书。U不表示永不会发生。

依据只取现有代码和材料：[固定映射对照](validation/fixed-mapping/checks.json)、[逐帧RAW](validation/fixed-mapping/raw-after.tsv.gz)、[G01/G02量数](validation/g01/results.json)、[G4条件摘要](validation/g01/summary-conditional.yaml)、[match-only统计](validation/match-only/metrics.json)。没有重跑生产链，也没有改阈值做消融。当前生产profile为空，G4的C证据不能冒充本片实测标定或MaixCam验证。仓库现行生产树没有G3/G5决策实现；“将来可能用”不计现有消费者，写YAML、画文字和测试断言也不计算法决策消费者。

优先裁决清单：

- **直接删减候选**：D05面积0门；D08/D10/D16三个角质量阈值和相应质量旗；P04–P12未启用安装/prior；L07/L08/L17等自证/恒定字段；L22/L23/L24等重复或空占位结果；G4中无人消费的资格汇总与预测支路。
- **经验质量门改信息候选**：D06的64px²冲突、D07的10点门、D09的5°门、D12/D13的3°/9px关联、D15的13.5px连接、D17的14px跨度、P01/P02的绝对误差、P03的0.25px差距、K04/K05的NIS、K06/K07/K08的方差和dt域。原始数值有消费者才留；无人据此决策就删阈值，不再生一层空标签。
- **保留的核心**：白片分割与真实MARK结构确认、连续支持和两线求交、候选排序、固定身份契约，以及真正的空值/越界/NaN/退化/错帧/无解保护。不能把“不满足MARK结构”统统改成标签然后仍发布MARK；它们是检测算法本体，不是拟合完成后叠加的质量门。

“门控改标签”是下一批的方向，不宣称只加一个字段即可完成：尤其G2的Unique/Ambiguous与G4的Unique准入需一起定语义，不能硬选近平面双解为Unique，也不能只改名却照旧拒绝。高NIS只证明模型与观测不一致，不能据此断言观测就是坏数据。旧任务要求保留的门，本次仍如实审查，实施与否交用户裁决。

清单共 **156项**（一项可覆盖同一谓词的重复位置；共用阈值的每种效果已展开说明）。每行均列出现行性质、实际消费者、证据等级与建议。
