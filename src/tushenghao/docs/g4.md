# G4 帧间跟踪与速度估计

## 完成内容

G4是独立`mark_tracking`库：消费G2当前`Unique`位姿，输出MARK物理原点P0的位置、速度、状态与模型条件下的不确定度。不改变Detector/G2接口，不写回Detection，不反馈PosePrior，不做决策或控制。

选用实际Δt的6维CV-KF，状态顺序固定`[px,py,pz,vx,vy,vz]`，单位m、m/s。首帧只有位置；两次不同时刻的有效观测才形成速度。原屏幕四角排序和姿态多解由G2负责，G4不猜。

关联采用位置创新NIS门控。多个候选同时合格则拒绝关联；门外唯一观测进入独立pending，两点一致可重建新ID，防止反转永久失锁。ID只表示几何连续估计区间，不保证遮挡期间物理身份没换。

状态为`MEASURED/COASTING/LOST`。非Unique状态或空帧不刷新最近实测时间；预测误差域超限后LOST，不带旧位置或速度。必须每帧调用step，包括没有观测的帧。

## 验证方法

从仓库根目录运行，保持单行命令：

```bash
sudo apt-get update && sudo apt-get install --no-install-recommends build-essential cmake pkg-config libopencv-dev libssl-dev libapriltag-dev
cmake -S src/tushenghao -B build/g4-release -DCMAKE_BUILD_TYPE=Release -DMARK_BUILD_G2=ON -DMARK_BUILD_G4=ON
cmake --build build/g4-release -j4
ctest --test-dir build/g4-release --output-on-failure
build/g4-release/tracking_app --check-config
build/g4-release/tracking_lab generate --out runs/g4-data-001
build/g4-release/tracking_lab calibrate --input runs/g4-data-001 --out runs/g4-calibration-001
build/g4-release/tracking_lab verify --input runs/g4-data-001 --profile runs/g4-calibration-001/profile.yaml --out runs/g4-holdout-001
build/g4-release/tracking_app --config runs/g4-calibration-001/tracking_research.yaml --input runs/g4-data-001/holdout/holdout-seed-2026104901/frames.yaml --out runs/g4-replay-001
```

输出目录必须不存在。默认tracking.yaml不带profile，检查配置可以通过，正式处理会要求先标定。默认实验是合成camera_relative/nominal_research，不能复制为实车profile。

`tracking_lab.yaml`中的坐标模式、时间政策改变后，重新calibrate到新目录；profile会保存模式，verify拒绝借用其他模式的profile。可用模式是camera_relative/local_world与nominal_research/bounded_only四个组合。实验时的world_frame_id为synthetic-world；实际车辆必须换成真实约定。

旧G2回放：

```bash
POSES=src/tushenghao/docs/evidence/g2/runs/g2-video-001/observations.yaml
build/g4-release/tracking_app --input "$POSES" --profile runs/g4-calibration-001/profile.yaml --out runs/g4-legacy-001
```

旧文件没有曝光/时间误差/完整协方差，reader明确降为LegacyG2Replay；不补字段、不授予硬件资格。若没有任何可用Unique，仍写诊断但退出码为2，不能写“端到端速度通过”。

`tracks.yaml`保存逐帧状态、事件、last_measurement_stamp、last_detection_index、协方差和资格；`summary.yaml`保存计数与step耗时；`effective_profile.yaml`与`tracking_config_input.yaml`保留有效配置。step耗时不含文件解析/写盘/上游检测。

## 踩坑记录

- 当前上游`30ac7ab`仍要求三项PnP预算齐全，而`min_quad_area_px2`为空，实际只能BudgetMissing。G4不能偷用其候选；真实端到端测量验收被该前置关卡阻塞。
- G2`covariance_se3_`没有数值和排列约定，不能取左上3×3或当零。用独立PositionNoise旁路或独立标定的camera位置MSE。
- target_id是模型类名、detection_index只是当前帧索引；不能作为永久ID。与G2方向衔接要用最近实测stamp+last_detection_index。
- 相机模式输出`d(p_camera)/dt`，包含自身平动/转动。场地0.5m/s不是该量的上限，不做限幅。
- 世界模式必须提供同曝光时刻的`^W T_C`；缺反馈只能在原坐标系coast，不能静默切回camera。Q/门控/std域也必须在所选坐标重新标定。
- 接收时刻不等于曝光。未知时间预算只允许名义研究；bounded_only缺时间质量则不更新，质量恢复后必要时重建，避免旧名义状态提权。
- 时间绝对界不是高斯σ。有界模式用保守MSE传播，未知相关用数学包络；这些仍以局部CV/噪声假设为条件，不能称物理绝对保证。
- 输入最大采样间隔与未来预测horizon不同。predict_to只读，以预测协方差域判可用；查询时刻必须属于当前clock_domain，执行时刻误差归G3/G5预算。
- observation_age_s是状态时刻减最近测量时刻，不是曝光到运行结束的总延迟。G5须用自己的当前单调时钟与stamp计算真实观测年龄。
- __FILE__定位默认配置；源树搬迁后重新编译，单独搬二进制需显式传--config与--profile。

## 已知限制

本期单track，不估计角速度；MARK P0不是框口中心。G5若转移到有偏置的框口，需同时间G2方向；旋转时的ω×r项不在本期估计结果内。

同类完全重合、遮挡中换位无法仅凭当前接口证明身份。两点确认是速度可观测与几何连续条件，不是物理实例证明。`Forecast.available`仅表示模型预测有数值可用；不能单独当资格，需同ID/会话当前结果、最新测量和误差预算。

三倍标准差仅用于同口径统计门槛；NIS/范数不一定正态，不承诺99.7%。R/Q是二阶矩而非门槛，固定偏差/时间相关也不能靠给R加大自动解决，需看独立holdout包含率。

合成实验直接生成3D观测，绕过G2，没有真实图像/FOV/轨道净行程/曝光偏移/轮滑验证。规则与图纸为参考，不是实物测量。所有实验均未经过实车确认。
