## 为什么这样拟合

参考了[OpenCV 4.6 ArUco轮廓线精修](https://github.com/opencv/opencv_contrib/blob/4.6.0/modules/aruco/src/aruco.cpp)的轮廓分段、拟合线、求交思路；[AprilTag refine_edges](https://github.com/AprilRobotics/apriltag/blob/master/apriltag.c)沿边法向梯度取支持再拟合/求交，取样机制不同，不能称为同一算法。没有引入ArUco依赖或复制第三方代码。

MARK不是一圈连续黑边：80×80外结构角分布于四个L/M白片，白片间有空隙，M也较短。因此每角只取自己的真实白片轮廓，粗四边形的两条边用于方向提示，不能沿整条框边把空隙当支持。115×120外板不参与四角；固定身份与拟合保持独立。

最终支持构造：最近粗角轮廓点作锚；双向各走不足半圈，以bbox跨度四分之一探针给分支定邻边，用±3像素局部切向作方向归组，只取首次连续段；起始跳过2+3像素、末端去2像素，去圆角/阶梯转折；每组至少两不同点。两线平行/非有限才数学无解，最终图内/凸环在发布时检查。

3像素半窗、2像素修剪和四分之一探针仍是算法的支持提取尺度，会影响结果；它们没有改名藏成质量门，也不宣称是跨设备已标定常量。两次L2的`reps/aeps=.01`保留原设置。局部支持不足时不拼接别的边、不补角。

支持方案在原基线配置上先做只读试验，未把试验代码接入生产：

## P03/G01的联合语义与G4对照

删除1.10px重投影预算与0.25px差距后，G2输出全部数学合法解，取最小RMSE作名义测量。两个解就标Ambiguous，绝不把“挑了一支”改名为Unique。G4同步接收其名义测量，并真实消费另一解的位置分歧：

`R_eff = R + Σ [e0²/(e0²+ej²)] (tj−t0)(tj−t0)^T`。

e0=最佳支RMSE，ej=另一支；实现先归一化防溢出；两误差均0时取1/2。它是无新增阈值的连续残差权重，**不是经过标定的后验概率或完整SE3协方差**。相同平移、不同旋转仍有姿态歧义，位置滤波不替它消歧。

试过不分RMSE的等权1/2，结果对测量跟随偏迟钝：本片自身名义PnP位置残差中位/P95/最大2.894/10.170/16.090mm，故未采用。最终连续权重保留同样简洁的公式，较差支不会与最佳支等权。没有加差距开关、NIS门或新调参。

G4复用历史[合成profile](validation/g01/reference-profile.yaml)的**原R/q/vv**，无再拟合：q=0.008264593245685344m²/s³，初速方差=0.13094478030685891m²/s²。原profile中的NIS/std/dt/元数据不再消费，验证用最小profile单独归档。生产配置没有填入此profile。时间未知，当前是相机系名义时间模型，非有界真实速度校准。

## 比赛与MaixCam待验

当前仍按规则V1.0.3的80×80 MARK、L/M白片、115×120外板分离建模，不引入方板边缘或通用黑框假设。规则尺寸及与V1.0.2差异沿用[已核对的规则依据](MATCH_ONLY_RULES.md)，本轮未改变比赛尺度。

1. 相机换装后重标K/dist/图像域、验固定P排列和小晃动上下带稳定；相机系速度含自车运动，不能直接套比赛0.5m/s作门。
2. 实拍覆盖最远小M、近距离圆角、曝光/反光、运动拖影/滚动快门。重验原/工作白阈200、epsilon=2、六尺度、22/80透视近似以及支持半窗3/trim2/probe-quarter，尤其短边不足和方向归组错误；不声称这些像素常量对任何分辨率都精度等价。
3. 将1676帧验证扩展到板端正/负样本、遮挡/截断、多目标与图案消失。不能为了留检测把不满足MARK结构变标签放行；若光照失败优先修分割/取支持，不堆后验质量门。
4. 用实拍独立位置/速度参考重标R/q/vv及双解残差权重，检查NIS序列、延迟和实际位置/速度误差；需要时替换连续误差权重模型，而非重新塞进Unique-only或差距拒绝。当前仅条件诊断。
5. 长coast输出保持预测含义，阶段结束/控制权切换由实际任务状态消费，不能拿coast当图案存在。板端测量CPU、内存、帧时延/曝光时间语义和实际帧率；桌面用时不外推MaixCam性能。
